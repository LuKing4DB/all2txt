# 通用 AI 规则 (Common AI Rules)

## 代码组织原则 (Code Organization Principle)

- **单一职责原则**：一个文件只解决一件事，保持文件职责清晰
- **优先解耦**：增加新功能时，优先创建新文件而不是扩展现有文件
- **文件大小限制**：单个文件行数控制在 300 行以内
- **模块化设计**：将复杂功能拆分为多个独立模块，便于维护和测试

### 实施指南

1. 新增功能时，先评估是否需要新文件
2. 当文件超过 300 行时，考虑拆分为多个文件
3. 提取重复逻辑为独立函数/模块
4. 保持导入关系清晰，避免循环依赖

## Commit Message 规范 (AI Commit)

- 所有提交信息必须使用中文。
- 遵循 Conventional Commits 规范：`<type>(<scope>): <summary>`。
- `summary` 不超过 72 字符，使用祈使句，避免句号。
- 如有必要，添加正文与页脚，正文每行不超过 72 字符。

### 可用 type

- feat: 新功能
- fix: 修复缺陷
- refactor: 重构（无功能变化）
- perf: 性能优化
- docs: 文档变更
- chore: 构建/依赖/杂项
- test: 测试相关
- style: 代码风格（无逻辑变化）

### 模板

```
<type>(<scope>): <中文摘要>

<变更动机或背景（可选）>
<主要修改点的要点式列表（可选）>

BREAKING CHANGE: <不兼容变更说明（如有）>
Issue: <关联问题编号（如有）>
```

### 示例

```
perf(converter): 合并遍历流程单次导出文本/图片/表格

- 通过 iter_lines 同步落盘图片与表格
- 移除二次遍历，减少 I/O 开销
- 完善注释与导出配置
```
